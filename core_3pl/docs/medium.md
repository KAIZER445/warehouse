What is hexagonal architecture

in domain driven design the core intension is to make the system modular or as close as modular to possible. in other words the purpose is to isolate different parts of the code structure strategically. in the most common architeture design the code that communicates with the database ,the code that takes request from clients, the code that connects them and the code that holds the busniess logic are seperated. surely the seperation is not superficial or for just good readbility its holds a greater purpose. to understand more clearly lets setup a hypothetical scenario: 

lets assume the database has been changed from postgres DB to maria DB and now its your responsibility to connect this new database to your system. if you had a big ball of mud code the migration to new database systems would be a process of rewriting the whole system. in such case one would only wish for a architure where he could just chnage the layer that talks to the database leaving the other parts untouched. this is one of the many use cases of the DDD. Similarly we can visualize the situation where we would need to swap payment methods from one to other where DDD shines as well. from these scenarios we can conlcude that any part of the architecure where there is scaling and updating action require due to chnaging requirements (which is inevitable in working environment) or for optimizing the codebase DDD is one of the best options which helps to alter the code with minimum restructuring.

As now we have learnt a gist about DDD now we should explore one of the many apporaches to implement DDD i.e hexagonal architecture. to make a reasonable transition we can identify ddd as a structuring philosophy and hexa as a approach to implement this philosophy. first lets understand why is it called hexagonal architecture. its obvious that a application might not have exactly six adapters and ports there can be many then why use hexagon why not use heptagon or octagon or a shape with most amount of poissible sides? well the reason is that the creator of the hexagonal architrcture used a hexagonal diagram to display the idea. hexagon does not imply one must only have six port and adapters its just a name therefore most engineers use the name ports and adapters architeture for a clearer picture.
